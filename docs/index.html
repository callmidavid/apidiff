How Apidiff Works

  1. API — The contract: the fields an application promises to provide, for example { email, name }.
  2. Diff — A comparison of the old and new contracts, similar to git diff but for APIs.
  3. Breaking — A removed, renamed, or type-changed field. Existing clients that rely on it will fail.
  4. Safe — An added field. Existing clients may ignore it without adverse behaviour.

Notes for the Reviewer

What does BREAKING mean?

If v2 is deployed as it stands, any client reading user.email will fail. Restore email, or release as /v2/users with a migration note.

What does SAFE mean?

Adding phone is safe. Existing clients ignore new fields. There is no loss of functionality.
